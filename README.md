# 华为产品场景营销工作台 v2

选择产品、受众、场景、营销目标和渠道，生成有原文依据、真实图片穿插排版的原创图文。支持文本下载，以及包含实际图片的独立 HTML 文件，下载后可离线打开。

## 当前范围

- 10款可创作华为电脑：仅展示有完整规格和本型号原图的型号。45个扩展发现条目保留在内部资料目录，不出现在选择器，也不接受其ID生成。
- 四营销目标：企业咨询、种草了解、到店咨询、选购决策，与渠道共同决定主题取舍、语气和行动引导。
- 四渠道：公众号、小红书、门店朋友圈、门店海报；各有篇幅、结构、语气、引导和图数规则。
- 八场景：开学季、职场差旅、内容创作、家庭换新、企业采购、门店到访、新品关注、节日送礼。
- 112张原始素材已查看总览，50张登记可用（含不同尺寸的同视角，生成时再次去重）。空白组件、条幅、无明确型号的功能广告或品牌标识不当独立产品图凑数。
- 已按用户2026-10-18最新要求取消双人签字门槛；历史审批记录保留，新版不再受其限制，但仍校验原文、指纹、数字和引用。

选择器标注每款可用原图数，同画面去重。少于渠道建议数时按实际配图并提示受限完成，不借用其他型号。切换营销目标会清空旧稿，修订不能串用其他目标的文案。

## 启动

当前电脑已配置环境与凭证，运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start.ps1 -Port 7861
```

打开 http://127.0.0.1:7861/ 。停止按 Ctrl+C。默认本地v7资料模式，只调用真实写作模型，不请求ima；页面持续说明原件日期与未验证远端当前最新。

新环境建议Python3.12：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\configure-modelscope.ps1
$env:MODELSCOPE_MODEL='Qwen/Qwen3.5-35B-A3B'
```

该模型在本机实际调用通过，其他账号权限和额度须实际验证。令牌隐藏输入，存入用户目录 `.config/modelscope/`。实时模式另运行 `tools/configure-ima.ps1` 配置ima凭证，不能填魔搭令牌。不要在聊天、仓库、截图或文档中放密钥。

## 私有资料

| 配置 | 默认位置与用途 |
|---|---|
| APP_KB_DIR | 项目下 `华为PC全板块深度知识库_v7`，含全库文件指纹清单 |
| APP_ASSET_REVIEW | `data/private/asset-review-v2.json`，实际画面、归属型号、原件SHA与排除理由 |
| MODELSCOPE_API_KEY / MODELSCOPE_MODEL | 模型凭证和模型ID，也可用用户目录配置 |
| IMA_OPENAPI_CLIENTID / IMA_OPENAPI_APIKEY | ima凭证，也可用用户目录配置 |
| data/private/runs | 实际输入、提示词、原始输出和核验记录，不公开上传 |
| data/private/exports | 本次TXT和包含实际图片的HTML |

公开源码包不含原文、原图、真实审核元数据和运行记录。新电脑须私下配置获授权原件；指纹不符即停止。空源码仍能打开界面，但不伪造目录、参数、图片或固定稿。

`tools/audit_asset_sheets.py` 只生成检查用缩略总览，不改原图。`tools/import_asset_review.py` 只适用于本次已经实际查看的112图v7排列；新版本必须重做图像核对，不能沿用旧序号。

## 不用看代码的验收

1. 产品下拉框只能选择，不接受键盘输入或自定义型号；选择后看资料范围、原文章节和对应素材数量。配件、打印机和仅有简介的条目不应出现。
2. 选择渠道、受众、场景和营销目标。版本和系统未知时保持“按资料区分”，不将不同配置拼成一台设备。
3. 标准/详细分别控制篇幅：公众号700–1050/1050–1700字，小红书350–550/550–850字，朋友圈90–160/160–260字，海报35–110/70–200字。补充说明可明确字数，修订要求中的新字数优先；“左右”有浮动，“以内”严格控制上限。结果栏显示实际采用的设置。
4. 设置期望图数。公众号2–4、小红书3–6、朋友圈1–3、海报1，受当前型号真实素材限制，不凑数。
5. 图文预览查看实际图片穿插排版；在“原文与来源”查引用，在“核验与素材”看检查和放大原图。
6. 修改详略、图片数、补充说明或修订要求会清空旧的可见结果和下载，但保留本次型号的上一稿供修订；更换型号、场景、目标、配置或模式会清空旧稿上下文。失败草稿仅作私有修订上下文，不显示为可用稿。生成期间锁定输入。
7. 下载HTML并离线打开，确认文字与实际图片都在。TXT含模式、状态、引用、来源和插入位置。

## 检查与打包

```powershell
.\.venv\Scripts\python.exe tools\run_checks.py
.\.venv\Scripts\python.exe tools\check_full_flow.py --run
.\.venv\Scripts\python.exe tools\package_release.py
```

第一条禁止连接器联网，不耗模型或ima额度；第二条真实运行四渠道，会使用模型额度，结果留在 `data/private/full-acceptance/`；第三条按明确清单打包公开源码并扫描已配置凭证。私有资料缺失时，相应真实资料检查明确跳过，不当已核。Git暂存后可运行 `tools/check_release.py`，扫描不覆盖远端历史。

## 架构和边界

新版入口 `app/ui.py → app/full_pipeline.py`，`catalog.py`管理全目录、原文与指纹，`channels.py`提供四渠道共享规则。写作前按渠道选择事实，之后校验可见引用、数字、条件和结构。程序可根据当前型号原文中唯一的数字匹配补充来源链接，并规范编号；不会给找不到的数字编造出处，原始输出和格式处理均留档。

整次生成最多4次模型请求，模型阶段共用120秒预算：一次创作，规则失败时最多一次定向修订，规则通过后一次表达复核，实际编辑后最多再复核一次。没有外层三轮重写；相同问题不反复循环。无用的模型图片文件名直接忽略，只用程序核对的原图；部分超字数稿先删除重复邀请或可省导语，再完整核验。用户重点参与事实检索，标题、关键词、表情、标签、字数与段数要求贯穿写作和复核。原稿、编辑、每次调用与用时均留档，未通过仍不展示可用稿。发布前仍需人工核对具体SKU和条件。

临时请求或Token吞吐限流会按5、10、20秒退避，并遵守服务返回的较长等待时间；每次实际请求（含重试）仍计入上述4次与120秒预算，等待期间显示真实进度。明确的免费额度、日额度或账户预算耗尽不自动重试。页面区分“模型服务受限”和内容核验问题，显示停止阶段与处理建议；原始错误、服务错误码和每次请求保留在私有运行记录。本地资料缓存只提供原文与图片，写作和表达复核仍依赖在线模型。

实时入口按所选产品真实目录读取ima，错误停止，不自动切本地。当天曾遇媒体限额，不能保证实时可用。Dockerfile已提供，容器构建、魔搭上线和私有资料注入尚未验证。部署时私有挂载完整资料目录与资产核对JSON，并设置上表路径，不打进公开镜像。

旧 `pipeline.py`、`whitelist.py` 保留为历史兼容与回归基线；新版生成不经过旧D14限制分支。系统提示词全文见 `prompts/system_prompt_v2.md`。本次扩容以本README为准，旧初赛设计和计划中的产品、签字、渠道限制已被用户最新要求覆盖。
